# KFM 统一知识表示与跨 benchmark 演示

中文配音为系统合成语音。网页实录使用人工场景；benchmark 数值来自已有验证报告。

## 00:00:00 多源数据

图、表、关系数据库、文档、图片文字和 JSON，常常各自独立。KFM 的目标，是保留它们的原生结构，接入一种显式知识表示，再通过共同接口执行不同任务。

多种载体，共同接口；保留结构、关联与来源。

## 00:00:13 统一表示

这是实际导出的知识包。表格行、图实体和文档块成为带类型的单元；关系和对齐成为关联。每个单元还记录原文件、定位信息和校验值，让计算结果能够回到证据。

实际 IR 浏览器 · 单元类型、内容、关联、原始来源

## 00:00:27 联合任务

以人工构造的采购任务为例。订单来自数据库，库存来自表，替代关系来自图，规则来自 Markdown，供应商状态来自文本标注。系统联接并检查约束，选择可交付的替代型号 B。

人工样例 · 显式键对齐、人工规则与文本标注 · 浏览器实时计算

## 00:00:41 知识更新

把风险阈值降到零点一，当前没有可行方案。再切换到恢复出货的新通知，型号 C 通过约束。点击更新通知，就能回到支撑这次选择的原文，看到更新如何改变结果。

风险阈值 0.10 · 通知 v1 → v2 · 无可行方案 → P-C

## 00:00:55 文档与图片

图片文字通过 OCR，PDF 通过文本提取进入统一表示。点击区域，可以查看文字和坐标。这里展示的是实际提取结果；图片场景理解和自动规则理解，还不属于当前实现。

实际 Poppler / Tesseract 提取 · 保留页码与区域坐标

## 00:01:11 跨 benchmark

跨 benchmark 执行从各自的适配器开始。原始数据进入知识包，任务接口读取所需视图，再调用对应的预测、图排序或 SQL 执行器。预测交回原评分器，测试答案留在评测侧。

流程说明 · Adapter → Knowledge IR → Task executor → Native scorer

## 00:01:26 执行记录

已有运行记录显示：Dry Bean 的表格预测准确率约为百分之八十八点六六；BIRD 的二十条参考 SQL 结果一致；WikiKG2 的原生与统一表示路径排序分数一致。这些验证说明兼容性，不是统一模型的成绩。

已完成运行的汇总记录 · 表格 accuracy / 图 MRR / SQL 结果一致性

## 00:01:43 学习边界

共享编码器可以插入召回环节。当前线性编码器在受控任务上改善，但冻结后迁移到 BIRD，完整支持集召回率仍低于词法基线。因此，跨 benchmark 的接口已经接通，通用表征的正迁移仍需要继续验证。

实测负迁移 · BIRD schema 检索不是官方 SQL 执行准确率
